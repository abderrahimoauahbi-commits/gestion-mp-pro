# Lot E1 — système de composants : ce que les lots suivants doivent savoir

Branche `lot-E1` (non fusionnée). `npm run verifier` : prettier, eslint, stylelint, tsc, vitest
(330 essais dont 152 pour E1, 66 fichiers d'essai sous `src/composants/`). Plafonds tenus
(400 lignes/fichier, 60 lignes/fonction). Vérifié au navigateur (Vite 5196, sans serveur) en
1366 × 768 et 375 × 812, clair et sombre.

## Où sont les choses
- `src/styles/jetons.css` : toutes les couleurs, clair **et sombre** (suit `prefers-color-scheme` ;
  `<html data-theme="clair|sombre">` le force). Jetons ajoutés : surfaces (`--surface-3`,
  `--survol`, `--ligne-marquee`), `--sur-accent`, `--sur-ton`, `--anneau`, `--bulle`, graphiques
  (`--graphe-*`), espacements (`--espace-1…5`), hauteurs (`--hauteur-bouton`, `--hauteur-champ`),
  fenêtres (`--fenetre-*`, `--tiroir`, `--cadre-fenetre`), atelier (`--barre-bas`,
  `--largeur-atelier`, `--entete-atelier`), plans (`--plan-liste|fenetre|messages`).
- `src/composants/{mise-en-page,tableaux,saisie,retour,graphiques,documents,atelier}/` : un
  composant = `Nom.tsx` + `Nom.module.css` + `Nom.test.tsx` (les contrôles de saisie partagent
  `saisie/controle.module.css`, les graphiques `graphiques/Graphique.module.css`).
- `src/composants/regles.test.ts` : un essai par composant, aucune couleur écrite dans les
  sources, aucune boîte du navigateur, vocabulaire retiré absent.
- `src/composants/atelier/atelier.test.tsx` : cibles ≥ 44 × 44 px (lues dans les feuilles).
- Démonstration (développement seulement) : `http://localhost:5196/src/composants/demonstration/index.html`
  (un faux serveur répond aux lectures ; la construction ne l'emporte pas).

## Pour E2 (coque)
- Poser **une fois** `<Messages />` (retour/Messages) à la racine de l'application (coque et
  atelier) : `dire(texte, ton)` et `direErreur(e)` s'en servent ; les erreurs restent jusqu'à
  fermeture.
- `Page({titre})` pose le titre d'onglet « {titre} — Gestion MP PRO » ; la page remplit le
  `<main>` : la coque doit donner au `<main>` une hauteur bornée (100vh − en-tête) pour que
  `Cadre` mesure juste.
- `Fenetre` retient `beforeunload` quand `sale`. La navigation interne (Précédent sur une fiche
  `/commandes/12`) n'est **pas** gardée : `BrowserRouter` n'a pas `useBlocker`. Si E2 passe à
  un routeur de données (`createBrowserRouter`), brancher `useBlocker(saisieEnCours())`
  (`mise-en-page/pile.ts`).
- `EcranReserve`, `EnTete` (fil, « ? »), `BarreLaterale` (avec `Pastille`), `RechercheGlobale`
  (avec `Selecteur` ou le motif combobox de `Selecteur`) restent à faire dans `coque/`.
- Icônes : `mise-en-page/Icone` (20 tracés) ; ajouter un tracé là, pas d'émoticône.

## Pour les lots F (écrans)
- **Liste** : `DataTable` + `useEtatTableAdresse(clés des filtres)` (recherche `?q=` et filtres
  dans l'adresse, « Effacer les filtres » d'un seul coup) ; `Colonne.recherche` pour les champs
  cachés, `rechercheCachee` pour ceux d'aucune colonne ; `unite` + `total: true` pour un pied par
  unité (jamais kg + ml, jamais deux devises) ; `exporter={{route:'/export/…', parametres:{onglet}}}`
  (q et filtres ajoutés seuls) ; `cliquable` pour ouvrir la fiche (`useFicheAdresse`) ;
  `lien` pour une cellule n° → document. Listes paginées : `useListePaginee(chemin, params)` +
  `serveur` + `total` + `chargerPlus`. La carte qui contient le tableau : `Carte serre remplir`.
- **Filtres liés** : options calculées sur les lignes qui passent les autres filtres et la
  recherche, avec leur nombre ; « N critère(s) » dès un critère ; « Effacer les filtres » dès
  **deux critères** (recherche comprise). `Filtre.options` fixe la liste en mode serveur.
- **Saisie** : `Grille` (1 à 4 colonnes, champs alignés par sous-grille) + `Champ` (libellé =
  nom accessible ; `erreur={erreurDuChamp(refus, 'chemin')}` pour un 422) ; `Champ groupe` pour
  segments, puces, quantité. `Nombre` (bornes et décimales dites à la frappe, `messageNombre` à
  reprendre dans le `manque` du bouton), `Quantite` (rend des kilos ; `borne` = ce qui est parti),
  `Prix`, `DateChamp` (borne haute = aujourd'hui du serveur, `futurPermis` pour une date prévue,
  `min` + `raisonMin` pour la période close), `Selecteur`, `SelecteurMatiere`, `SelecteurLot`.
- **Gestes** : `Bouton` ne se grise **que** par `manque`, `blocages` (du serveur), `grise` (une
  raison) ou un envoi en cours ; la raison est dans `data-raison` (la recette V3 peut chercher
  `button:disabled:not([data-raison])`). Un `onClick` qui rend une promesse occupe le bouton et
  dit le refus. `Confirmer` pour tout geste irréversible (motif `exige` / `facultatif`) ;
  `FenetreConfirmation` pour restauration, clôture de dossier, clôture de période seulement.
  Dans une fenêtre, « Annuler » / « Fermer » passent par `useFermerFenetre()` (garde `sale`).
- **Retour** : `Kpi` exige `formule` (le texte vient de `aide.json`, `formule.<cle>`) ; `Badge`
  lit `lib/statuts.ts` (`famille`, `valeur`) ; `Erreur` dit « Pas de réseau » (statut 0 ou
  `serveur_absent`) avec « Réessayer » ; `Chargement`, `Vide` (dire pourquoi).
- **Graphiques** : séries `{nom, valeurs, couleur?, unite}` ; une unité par axe (deux devises :
  deux panneaux) ; couleur du fil par `teinteDuFil` / `stylesDesFils` ; trait posé seul à teinte
  égale.
- **Documents** : `PiecesJointes({objet, id, lectureSeule})`, `Historique({objet, id})`,
  `LienDocument({genre, id, numero, statut})`, `BoutonImprimer({route, parametres})`.
- **Atelier** (F3) : `EcranAtelier({titre, retour, enTete, pied})` avec `BarreBas` ;
  `BandeauBlocages` en `enTete`, `ResumeValidation` en `pied` ; `Quantite tactile` ou `Compteur` ;
  `useSaisieGardee(cle, initial)` pour chaque saisie (oublier après enregistrement) ; `ScanQR`
  (BarcodeDetector, sinon recherche par numéro) et `lotDuQR`. `Bouton taille="atelier"` écrit sa
  raison sous lui ; `Confirmer taille="atelier"` prend toute la largeur.

## Pour les lots serveur (S2, D) — formes attendues, provisoires dans l'écran
Tant que l'OpenAPI ne les publie pas, ces types sont écrits dans les composants ; à remplacer par
`Schema<…>` (et le serveur peut s'y conformer) :
- `blocages: string[]` (phrases complètes, affichées telles quelles).
- `GET /pieces?objet=&id=` → `[{id, nom, genre, taille (octets), par, joint_le}]` ; `POST /pieces`
  multipart `objet`, `id`, `fichier`.
- `GET /historique/{objet}/{id}` → `[{id, quand, par, action, detail?, changements?: [{libelle, avant, apres}]}]`.
- `GET /lots/disponibles?matiere=&date=&magasin=` → `[{id, numero, reste_kg, date_entree?, magasin?, quarantaine?}]`, ordre FIFO.
- `Page[T]` = `{elements, total, suivant}` (curseur `?apres=`), déjà dans `lib/types.ts`.

## Décisions prises (à relire par le coordinateur)
1. Titre d'onglet « … — Gestion MP PRO » (ECRANS-PRO dit « — Gestion MP » ; aligné sur `index.html` d'E0).
2. « Effacer les filtres » dès deux critères posés (la recherche compte), et il efface aussi la recherche (comme Gestion MP).
3. Pas de pagination visuelle ; « Charger les 500 suivants » / « les N derniers » / « le dernier ».
4. Thème sombre par jetons dupliqués (pas `light-dark()`, ignoré des iPhone d'avant iOS 17.5).
5. La recherche affiche la frappe tout de suite et range l'adresse ensuite (le routeur écrit
   l'adresse dans une transition : sans ce relais, des lettres arrivaient en retard).
6. Les courbes serrent leur axe (zéro non imposé) ; les barres partent de zéro.
7. Export CSV côté écran (`exporter={{fichier}}`) seulement pour une liste sans export serveur ; `Colonne.exporte` y sert.
8. Démonstration sous `composants/demonstration/` (pas de fichier hors du périmètre d'E1).
9. Les essais qui lisent des feuilles de style chargent les types Node par `/// <reference types="node" />` (Vitest ne rend pas le texte d'un `.css?raw`).
