# Lot D5 — opérations, « À valider », inventaires : ce que les lots suivants doivent savoir

Branche `lot-D5`. `make verifier` vert (ruff, format, mypy strict, pytest : 1 700 essais environ
dont 39 du lot D5, `alembic check`, écran). Routes faites : **115–123** (opérations, brouillons,
« Tout valider »), **124–133** (inventaires, feuille de comptage), **239–241** (classeurs),
**245** (annulation d'un inventaire validé). Aucune révision Alembic, aucun fichier d'un autre
lot modifié.

## 2. Pour les autres lots

- **D6 (ordres)** : « À valider » lit les ordres si `services/ordres.py` définit
  `GENRE_BROUILLON`, un objet qui suit `services.brouillons.Genre` : `nom = "ordre"`,
  `lister(s, qui) -> list[Brouillon]` (avec `rang=droits.RANG["ordre"]` = 3, `peut_valider`,
  `raison` si non, `valide_par`, `blocages`, `lien="/ordres/{id}"`) et `valider(s, qui, id,
  version | None) -> numéro` (la même fonction que la route de validation à l'unité ; aucun
  commit : « Tout valider » pose un `SAVEPOINT` par document). `brouillons.MODULES` l'importe à
  la première lecture. Un retour des machines se rattache à un ordre `valide` ; le net sorti par
  lot = −Σ des mouvements portant `ordre_id` (sorties, retours, contre-passations). Annuler un
  ordre doit supprimer ses brouillons de retour (`Operation.ordre_id`, statut brouillon : B.13-13).
- **D4 (réceptions)** : même registre (`nom = "reception"`, rôles D, A) ; donner `rang=0`
  (une réception apporte la matière, comme une ouverture). Le registre range les réceptions dans
  `Brouillons.receptions`.
- **D3, D4 (commandes)** : `services.operations.RECALAGES.append(f)` où
  `f(s, qui, lots: set[int], raison: str)` recale les bons des lots : appelé après un retour au
  fournisseur et après **tout** transfert, validés (« retour au fournisseur », « sortie de
  quarantaine ») ou annulés (« TRF-2026-0007 annulé ») — S118. Aujourd'hui personne n'y est
  inscrit : le bon soldé par une libération (`test_parcours::test_la_quarantaine_se_libere…`) est
  à prouver par D3/D4 en s'y inscrivant.
- **D1** : `TYPES_MOTIF` est la source de la table des droits par type ; la changer change les
  droits du serveur.
- **F2, F3, F6 (écrans)** : `OperationFiche` porte `peut_agir` et `raison` (droit du lecteur sur
  ce document, quarantaine comprise), `liberation`, `mise_en_quarantaine`, `blocages`, `version` ;
  `InventaireFiche` porte `perimetre` (texte), `criteres`, `blocages` (Valider grisé avec la
  raison, N2), `quatre_yeux` par ligne et `recomptes_meme_personne`, `sans_justification`.
  « Tout valider » : `POST /brouillons/valider` `{tous: true}` ou `{documents: [{genre, id,
  version}]}` ; réponse `{valides, refuses, ignores}` chacun `[{genre, type, id, date, libelle,
  resume, lien, numero, raison}]`. La feuille : `GET /documents/inventaires/{id}/feuille
  ?recomptage=&theorique=` (nouvel onglet). H-19 : pour un document antidaté, proposer les lots
  par `GET /lots/disponibles?date=` (S4) ; les blocages jugent déjà à la date du document.
- **Essais qui valident leurs données** : un inventaire validé en base par un essai doit être daté
  d'une autre année que 2026 (`JOUR_DES_INVENTAIRES`, 31/12/2025) : le monde de S1
  (`tests/modele_monde.py`) pose `INV-2026-0001` à la main, et `test_periode` échoue sinon.
  `fabriques.operations.monde` crée ses propres magasins (courant et quarantaine) : du stock posé
  dans les magasins semés casse les essais de D1 (désactivation d'un magasin).

## 3. Décisions (documents muets ou contradictoires)

1. **Un inventaire ouvert par magasin**, un inventaire de tous les magasins exclut tout autre :
   c'est l'index unique `uq_inventaire_ouvert_magasin` de S1 (ECRANS-PRO parlait de périmètres
   qui se recoupent). Vérifié sous le verrou `INVENTAIRE_GLOBAL` ; messages de Gestion MP corrigé
   (C-07 : « … déjà ouvert sur « CODE ». », « … sur tous les magasins. », et la suite « : un
   inventaire de tous les magasins attend qu'il soit validé ou abandonné. »).
2. **Périmètre** : sans critère, toutes les matières sont écrites dans `inventaire_matiere` (un
   inventaire de tout le stock suspend aussi l'entrée d'une matière qui n'y était pas, comme
   Gestion MP) ; avec critères, les matières qui les passent tous, plus celles des lots figés ;
   un lot trouvé d'une matière hors périmètre l'y ajoute. Une matière sans classe ABC du jour est
   rangée en C (comme le tournant).
3. **Abandon** : statut `abandonne`, numéro, comptages et lignes **gardés** (ECRANS-PRO ; Gestion
   MP corrigé vidait les lignes) ; motif exigé (≥ 3, « Dire pourquoi l'inventaire est
   abandonné. ») rangé dans `inventaire.annulation_motif` (pas de colonne propre, voir § 4).
4. **Annulation d'un inventaire (245)** : refusée si un inventaire ouvert **suspend une matière
   ajustée dans son magasin** (K2) plutôt que « couvre ses magasins » ; message de Gestion MP
   corrigé. Un inventaire validé sans écart s'annule sans mouvement.
5. **Quarantaine** (décision de Mohamed) : libérer = direction et achats (403, OR24 mot pour mot :
   « … décision des achats, après contrôle de la matière. » — ECRANS-PRO proposait « des achats ou
   de la direction », non repris : REGLES fait foi) ; le motif « Libération de quarantaine » est
   refusé à l'alimentation même hors quarantaine (`motif.impose_role`) ; mettre en quarantaine :
   D, A, L, observations ≥ 3 (« Une mise en quarantaine se justifie : écrire ce qui est
   douteux. ») ; C-01 : messages de Gestion MP corrigé (« Supprimer une libération de quarantaine
   est une décision des achats. », « Annuler une mise en quarantaine en ferait sortir la
   matière : … »).
6. Messages nouveaux ou adaptés : OR16 « … manque (ou cocher « Lot interne »). » ; « Une matière
   retrouvée s'ajoute au stock : sens « + ». » (lot à créer ou motif « Matière retrouvée ») ; C-09
   « Motif « X » inconnu pour « Type » : choisir parmi … » (ou « ce type d'opération n'en prend
   pas ») ; « Rôle inconnu : n° … », « Composition inconnue : n° … » ; « Choisir les documents à
   valider, ou demander de tout valider. » (422 si le corps de 123 est vide) ; « Cette opération
   est déjà annulée. » ; unités : messages OR13, OR14 et D-08 de Gestion MP corrigé (la palette
   peut être entamée, la bobine non).
7. L'annulation d'une opération prend un **motif facultatif** (`annulation_motif`, l'écran n'en
   demande pas) ; celle d'un inventaire l'exige (≥ 3).
8. Numéro d'une opération donné à la validation, **en même temps** que le statut (contrainte
   `numero ⇔ validée`) ; un refus pendant l'écriture annule tout (aucun trou).
9. Lot trouvé : journal « lot trouvé » ; le premier compteur (`compte_par_id`) et le recompteur
   (`second_par_id`) sont notés ; « même personne » signalé (jamais refusé).
10. « Tout valider » : un document choisi qui n'est plus brouillon est quand même tenté (sa raison
    est celle de la validation à l'unité) ; une `IntegrityError` d'un document est rendue en
    refus, les autres continuent.

## 4. Écarts aux documents (à reporter par le coordinateur)

- **MODELE-DONNEES** : `inventaire` n'a pas de colonne pour le motif d'abandon ; il est rangé dans
  `annulation_motif` (états exclusifs). Demande à S1 : `abandon_motif` (ou renommer en `motif`).
- **API-PRO 122** : `Brouillons` porte aussi `lignes` (tous, dans l'ordre de validation) et chaque
  élément `version`, `raison`, `valide_par` ; **123** : clés `valides`, `refuses`, `ignores`
  (sans accents ; `ignores` = le `non_permis` de Gestion MP corrigé, C-17), chaque élément avec
  sa `raison`.
- **API-PRO 115–121** : `OperationFiche` + `peut_agir`, `raison`, `liberation`,
  `mise_en_quarantaine`, `valeurs [{devise, montant}]`, `annulee_par`, `annulee_le`,
  `annulation_motif`, `version` ; `fournisseur_id` de l'entrée est ignoré (celui des lots, S101).
  Liste : `?type=&statut=&q=&apres=&limite=`.
- **API-PRO 124–127** : `InventaireResume`/`Fiche` + `perimetre`, `criteres`,
  `nb_matieres_suspendues`, `abandonne_par/le`, `annule_par/le`, `annulation_motif`,
  `sans_justification`, `recomptes_meme_personne`, `version` ; lignes + `lot_trouve`,
  `lot_interne`, `compte_par`, `quatre_yeux`, `ecart_pourcent` ; `DefautsInventaire.roles` et
  `compositions` en `[{id, code}]` (Gestion MP : des codes) ; 126 : `?magasin=`.
- **ECRANS-PRO P6** : conflit d'inventaires par magasin (décision 1), pas par périmètre ; OR24
  (décision 5).
