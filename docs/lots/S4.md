# Lot S4 — chargeur du moteur, écriture du stock, lots : ce que les lots suivants doivent savoir

Branche `lot-S4`. `make verifier` vert (1 300 essais environ, dont ≈ 50 de S4). Services,
routes 103–113 et 236, classeurs, essais ; la route 114 (étiquettes) est rendue par D9.

## 1. Écrire du stock : `services/stock.py`, le seul chemin

```python
from gestion_mp_pro.services import stock
from gestion_mp_pro.modeles.enums import DocumentMouvement, TypeMouvement

piece = stock.Piece(DocumentMouvement.operation, op.id, op.numero)   # reception|ordre|operation|inventaire|reprise
m = stock.ecrire(s, type=TypeMouvement.SORTIE, lot=lot, magasin_id=g.id, quantite=-70,  # kg signés
                 jour=op.date, piece=piece, auteur_id=qui.id,
                 prix=0, devise="MAD", cours=None,                   # entrées : prix au kg, cours figé
                 liens=stock.Liens(ordre_id=…, motif_id=…, motif_texte="", commentaire=""))
stock.transferer(s, lot=…, source_id=…, destination_id=…, quantite=40, jour=…, piece=…,
                 auteur_id=…, motif_id=…)                            # deux lignes liées (paire_id)
stock.contrepasser(s, piece, qui.id)                 # tout le document, une fois (SR12)
stock.contrepasser_mouvements(s, [m1, m2], qui.id)   # des lignes choisies (ordre repris…)
lot = stock.lot_ou_creer(s, matiere_id, "L-123", jour, fournisseur_id=…, poids_bobine=2.5)
lot = lots.lot_interne(s, matiere_id, jour)          # LOT-AAAA-NNNN donné à la validation
```

- **Personne d'autre n'écrit `Mouvement(`** (ni `insert(Mouvement)`, ni SQL) hors de
  `services/stock.py` et de `reprise/` : `test_ecriture_stock::test_seul_chemin_d_ecriture`
  (analyse AST) le vérifie à chaque `make verifier`.
- `ecrire` : quantité arrondie au gramme (`Decimal`) ; dans l'ordre : SR1 (nulle, 422
  `quantite_invalide`), `periode.date_permise` (S2), SR3/SR4 (magasin inconnu / désactivé qui
  reçoit, 422), **verrou du solde** (`FOR UPDATE`), SR5 (inventaire ouvert, 409
  `inventaire_en_cours`), SR6 (solde < 0, 409 `stock_insuffisant`), SR8/SR9 (couvert à sa date,
  409 `lot_absent_a_la_date` / `stock_insuffisant`), cours figé, solde mis à jour, `flush`
  (l'id est connu). Messages mot pour mot (REGLES). **Aucun commit** : la route (SessionDep)
  valide tout ou rien.
- **Suspension par inventaire limitée au périmètre (K2)** : un inventaire `ouvert` sur le
  magasin (ou global, `magasin_id NULL`) ne suspend que les matières de son `inventaire_matiere`.
  **D5** : remplir `inventaire_matiere` à l'ouverture (matières des lignes + matières des
  critères) ; ouvrir après avoir pris les verrous des soldes comptés si l'on veut « attendre le
  mouvement en cours » (S14). Les écritures `piece.genre == inventaire` ne sont jamais
  suspendues.
- Cours (S18) : MAD → `NULL` ; devise avec prix → `cours` donné (figé par la commande), sinon
  le cours du jour de `devise` ; prix nul → le cours donné ou `NULL` ; devise inconnue → 422.
- Contre-passation : même type, quantité opposée, **datée de l'original**, même document,
  prix, devise, cours, ordre, motif ; « Annulation du mouvement n°… » ; sorties défaites
  d'abord ; une paire de transfert reste une paire. Deux annulations simultanées : la seconde
  reçoit 409 `deja_annule` (contrainte `uq_mouvement_contrepasse_id` traduite).
- Le journal est immuable : une jambe de transfert se nomme elle-même en prenant son id
  d'avance (`nextval`), jamais par `UPDATE`.
- Règles lisibles sans verrou (blocages d'un brouillon, lots D) : `services/stock_regles.py`
  (`couvert_a_sa_date`, `inventaire_qui_suspend`, `verifier_solde`, `cours_fige`).

## 2. Charger le moteur : `services/donnees_moteur.py`

```python
from gestion_mp_pro.services import donnees_moteur
d = donnees_moteur.charger_au(s, jour)          # a_la_date(charger(s), jour, aujourd_hui)
lignes = etat_stock(d, jour)
complet = donnees_moteur.charger(s)             # pour controler(…, complet=complet)
d0 = donnees_moteur.charger(s, avec_journal=False)   # sans journal ni soldes (plus rapide)
```

- Traduction fidèle de `gestion_mp/depot._charger` (CALCULS A § 4), table par table, dans
  `services/chargeur/` (contexte, référentiels, qualités, achats, réceptions, journal,
  production). Nombre de requêtes **fixe** (≈ 60, essai `test_aucune_requete_par_ligne`).
- Aides publiques (mêmes règles que Gestion MP) : `recu_par_ligne(s, net=True)`,
  `retours_par_ligne_reception(s)`, `en_quarantaine_par_ligne(s)`, `poids_bobine_mesures(s)`,
  `parametres(s)`.
- Instants rendus **sans fuseau, à l'heure de l'usine** (comme le journal de Gestion MP).
- Choix de traduction (à respecter par D2, D3, R1) :
  - `plan_version` : la **première** version d'une qualité est le plan « d'avant » (en vigueur
    depuis toujours), chaque suivante un changement ; une seule version = plan sans histoire.
    **D2** écrit une version à la création de la qualité puis une à chaque changement ; **R1**
    écrit la version « avant » puis les changements du journal.
  - Bon soldé à la main : `statut = soldee`, `solde_origine = manuel`, `solde_le` ; annulé :
    `solde_le` (sauf `solde_origine = reprise`, sans date).
  - Contrôleur qualité d'une réception : `controle_par`, sinon le nom de qui l'a validée (K5).
  - Lot d'une ligne reçue : le lot créé (`lot_id`), sinon `lot_numero`.
  - Entrées reprises de l'ERP Fil sans réception : `document = 'reprise'`, type `RECEPTION` ;
    leur ligne de réception se retrouve par lot, date et pesée (comme Gestion MP).
  - Dossier annulé, réception annulée : absents du moteur.
- **Cache** : clé = `signature(s)` lue en base à chaque appel (jour, `max(journal.id)`,
  `max(mouvement.id)`, `max(parametre.modifie_le)`, `count(mouvement)`, `Σ solde.quantite`).
  **Chaque geste doit écrire au journal** (`services.audit`, S2) : un geste qui ne change ni
  journal, ni mouvement, ni réglage, ni solde (un brouillon modifié sans journal) laisserait le
  cache ancien. `donnees_moteur.invalider()` vide le cache du processus (reprise, essais).
- **Ne jamais modifier en place** les `Donnees` rendues (partagées entre requêtes).

## 3. Lots : `services/lots.py`, `services/lots_lecture.py`, `services/conversions.py`

- `lots.lister(s, FiltresLots(matiere_id, magasin_id, statut, non_nuls, q, jour))` (route 107) :
  soldes par magasin, statut calculé (`disponible | partiel | quarantaine | epuise`), bobines,
  histoire (entré, sorti net, dernier mouvement, ordres) ; `q` = `normaliser` (sans accents).
- `lots_lecture.presents_au(s, {(lot, magasin)}, jour)` : ce qu'un lot pouvait donner à une
  date passée (min des cumuls futurs) ; `disponibles(s, matiere_id, magasin_id, jour)` (FIFO,
  hors quarantaine) ; `scan(s, code)` (adresse `…/lot/123` ou numéro, liste : un numéro peut
  exister pour deux matières) ; `etiquettes(s, "1,2,3")` (données des étiquettes, identifiants
  ignorés dits — **D9** les rend en HTML).
- `conversions` : `Unite`, `conditionnement(matiere, lot)`, `vers_kg(q, unite, c)` (422
  `unite_invalide` si le poids est inconnu), `bobines`, `metres`, `kg_et_metres`, `kg`.

## 7. Signalé (pour R1, le coordinateur)

Constats faits en réécrivant le jeu réel en base PRO — **R1 doit les traiter** :

1. Gestion MP écrit un **prix sur les sorties et transferts** (8 586 sorties du jeu) ;
   `ck_mouvement_prix_entree` le refuse : la reprise doit le mettre à 0 (sans effet sur les
   coûts : vérifié par le jeu).
2. **Camion en deux devises** (LOMAT : USD et EUR sur une même réception, 4 réceptions) : PRO
   garde une devise par réception (I35). Les prix payés de la seconde devise prennent celle de
   la réception dans l'essai ; R1 doit décider (scinder la réception, ou le déclarer).
3. Matière dont l'unité d'achat n'est pas le kg mais sans contenance (0) : `ck_matiere_contenance_positive`
   refuse 0 ; la reprise met l'unité à « kg » (le moteur ne s'en sert pas sans contenance).
4. Une **réception en brouillon numérotée** (REC-2026-0276) : PRO refuse un numéro sur un
   brouillon (M65).
5. Ordres validés **sans date de validation** (tout l'ERP Fil) : PRO l'exige ; midi du jour.
6. La jambe d'arrivée d'un transfert a, dans Gestion MP, le numéro qui suit le départ (27 trous
   dans le jeu) : à garder pour que l'ordre du journal reste le même.
7. Entrées de réception reprises de l'ERP Fil sans réception : `document = 'reprise'` (le
   chargeur les apparie par lot, date et pesée).
