# Lot E2 — coque, navigation, connexion, aide : ce que les lots suivants doivent savoir

Branche `lot-E2` (main fusionnée : S2, S3). `npm run verifier` vert (prettier, eslint, stylelint,
tsc, vitest). Vérifié au navigateur en 1366 × 768 et 375 × 812, clair et sombre, pour les quatre
rôles : d'abord contre un faux serveur conforme au contrat, puis contre le vrai serveur de S2
(base `gestion_mp_pro_e2_essai`, supprimée ensuite) : installation, connexion par visage au 4ᵉ
chiffre, refus, contexte, session perdue.

## Ce qui existe
- **Routeur de données** (`App.tsx`, `createBrowserRouter`) : `/connexion`, `/installation`,
  `/enroler` publics ; tout le reste derrière `FournisseurSession` (`lib/session.tsx`, GET
  `/contexte`) ; `/` → accueil du rôle ; `/lot/:id` → `/atelier/lots/:id` (téléphone **et**
  alimentation) sinon `/lots/:id` ; `/guide` → `/aide` ; écrans `atelier: true` hors coque ; les
  autres dans `Coque` ; adresse inconnue → accueil + bandeau. `main.tsx` ne pose plus de
  `BrowserRouter`.
- **Registre** `routes.ts` : agrège seul `pages/*/ecrans.ts` (`import.meta.glob`) ; `ORDRE_DU_MENU`
  fixe l'ordre du menu (ECRANS-PRO § 2.1). Chaque domaine a déjà son `ecrans.ts`, pré-rempli de son
  entrée de menu (et des fiches citées par l'aide) avec la page « à venir » (`EcranAVenir`).
- **Droits** `lib/droits.ts` : `permis(role, adresse)` (écran **et** onglet), `refus`,
  `ongletsPermis(ecran, role)`, `accueilDe(role, telephone)`, `menuDe(role)`, `estTelephone()`
  (`(max-width: 700px) and (pointer: coarse)`), `LIBELLES_ROLES`, `ROLES_METIER`.
- **Coque** `composants/coque/` : `Coque`, `BarreLaterale` (pastilles : Stock = `alerte_rouge`,
  Analyse = `anomalies` → `?onglet=controles`, Commandes = `a_approuver` (D), Réceptions =
  `receptions_brouillon`), `FilAriane` (automatique), `EnTete`, `RechercheGlobale` (« / » ou Ctrl K,
  ↑ ↓ Entrée Échap), `Cloche`, `MenuCompte` (déconnexion confirmée), `SignalerBesoin`,
  `BandeauServeur`, `EcranReserve`, `AideEcran` (tiroir du « ? »), `TexteAide`, `GardeEcran`,
  `GardeNavigation` + `garde.ts`, `EcranAVenir`, `EcranCentre`.
- **Aide** `aide.json` + `lib/aide.ts` ; `/aide` (7 onglets) ; `/compte` ; `docs/NOTICE.md` générée
  par `scripts/generer_notice.py` (un essai vitest échoue si elle n'est pas à jour).
- **Essais** : `src/essais/monter.tsx` — `fauxServeur({'GET /contexte': …})`,
  `reponsesConnecte(role)`, `monterApp(adresse)` (l'application entière, routeur de mémoire),

  (à mettre en `beforeAll` dès qu'on monte l'application : vitest n'attend pas un import à la
  demande déjà en cours).

## Déclarer un écran (lots F)
Dans `pages/<domaine>/ecrans.ts`, remplacer `page: aVenir` par sa page, et ajouter les fiches :

```ts
{
  chemin: '/commandes/:id',          // fiche en fenêtre sur la liste (adresse stable, A5)
  titre: 'Commande',                 // titre de la page ; pour une entrée de menu = libellé du menu
  parent: '/commandes',              // fil d'Ariane et entrée de menu active
  roles: ['direction', 'achats'],    // la direction est nommée ; jamais 'administrateur' hors technique
  aide: 'commandes',                 // clé de aide.json (tsc refuse une clé absente)
  onglets: [{ cle: 'prix', libelle: 'Prix du fournisseur', court: 'Prix', roles: ['direction', 'achats'] }],
  page: () => import('./Commandes'), // export default ; la liste qui ouvre la fiche (useFicheAdresse)
}
```
- Ne pas toucher `groupe`, `titre`, `roles` d'une entrée de menu sans changer ECRANS-PRO § 2.1 :
  `routes.test.ts` compare le menu de chaque rôle au tableau.
- Une fiche ouverte sur sa liste déclare la **même page** que la liste (`/commandes` et
  `/commandes/:id` → `./Commandes`) : la page lit `useFicheAdresse('/commandes')`.
- Un chemin fixe passe avant un chemin à paramètre (`/commandes/nouvelle` avant `/commandes/:id`).
- Onglets : `ongletsPermis(ecran, role)` donne ceux du rôle, le premier est le défaut ;
  `useOngletAdresse(cles, cles[0])`. La garde refuse déjà un `?onglet=` réservé (accueil + bandeau).
- Une page : `<Page titre><EnTete titre sous actions /> … </Page>` ; le `<main>` est borné, la page
  le remplit, seuls les `Cadre` défilent. Le « ? » de l'`EnTete` ouvre `aide.ecran.<cle>` de
  l'écran courant (`aide="autre_cle"` pour une autre, `aide={false}` pour aucune). Au second
  niveau d'une page (pas d'une fenêtre), passer `fil`.
- Liens : `permis(role, adresse)` avant de rendre un lien vers un autre écran ; `TexteAide` /
  `LienAide` le font pour les textes.

## Aide (`aide.json`)
- Chaque lot F n'écrit que `ecran.<cle>` de ses écrans (`{titre, resume, points[]}`) et
  `formule.<cle>` de ses indicateurs (`{grandeur, texte}`), **clés triées** (un essai le vérifie).
- Écriture : `**gras**`, `*italique*`, `[libellé](/chemin)` (lien filtré par rôle ; un essai
  vérifie que chaque chemin vise un écran déclaré), `{{sur_les_metiers}}` (texte unique).
- `Kpi formule={formule('valeur_stock')}` (`lib/aide.ts`) ; une formule citée par
  `mode_emploi.calculs.lignes` apparaît aussi dans « Les calculs ».
- Après tout changement : `python3 scripts/generer_notice.py` (sinon `notice.test.ts` échoue).

## Garde de saisie
- Une `Fenetre({sale})` est déjà gardée. Une saisie posée **à même la page** appelle
  `useGardeSaisie(sale)` (`composants/coque/garde.ts`).
- Tant qu'une saisie est en cours : « Précédent »/« Suivant » (`useBlocker`), tout clic sur un lien
  interne (menu, fil, n° de document) et les gestes de la coque (`proteger(action)`) demandent
  « Des modifications ne sont pas enregistrées. Les abandonner ? ».
- Les navigations **programmées par la page** (fermer après « Enregistrer », « Oui, abandonner »
  d'une fenêtre) ne sont pas retenues : c'est voulu. Un geste de page qui quitte la page **sans**
  avoir enregistré passe par `proteger(() => naviguer(…))`.
- L'atelier : `useSaisieGardee` (E1) pour garder la saisie, `useGardeSaisie(sale)` pour retenir
  la sortie ; le « ‹ » d'`EcranAtelier` (`navigate(-1)`) est retenu comme « Précédent ».

## Décisions
1. Menu : `ORDRE_DU_MENU` dans `routes.ts` (E2), écrans dans `pages/*/ecrans.ts` (F) ; les
   `ecrans.ts` sont **pré-remplis** (entrées du menu, et `/lots/:id`, `/atelier/lots/:id`,
   `/tracabilite`, `/commandes/nouvelle`, `/receptions/nouvelle`, `/ordres/nouveau`,
   `/inventaires/nouveau` que l'aide cite) avec la page « à venir », pour que menu, garde, arrivée
   et `/lot/:id` s'essaient dès E2.
2. Garde : `useBlocker` pour POP seulement + capture des clics sur liens + `proteger` ; pas de
   blocage des `navigate()` de page (sinon « Enregistrer puis fermer » poserait la question).
   Aucun fichier d'E1 changé pour cela.
3. Un onglet réservé est refusé comme un écran (accueil + bandeau), pas silencieusement remplacé.
4. Motif de session perdue : texte du serveur, sauf « Connectez-vous… » ou vide → « Votre session
   a expiré : reconnectez-vous. » ; « … plus actif » → « Ce compte n'est plus actif : voyez la
   direction. » (H-09).
5. Connexion par visage : `{compte: id, identifiant: '', code}` (S2, F-02) ; ailleurs
   `{identifiant, code}`, identifiant mis en minuscules.
6. Apparence (clair / sombre / poste) dans Mon compte, retenue par le navigateur ; l'impression se
   fait toujours en clair (`beforeprint`). `styles/impression.css` : A4, sans coque, cadres dépliés.
7. Icônes ajoutées à `mise-en-page/Icone` : aide, cloche, compte, deconnexion, menu, signaler.
8. Le téléphone de la direction ou des achats reste dans la coque (menu en tiroir) ; seule
   l'alimentation arrive sur l'atelier au téléphone.

## Types de l'API
`types.gen.ts` est régénéré depuis l'OpenAPI de S2 (`scripts/generer_types.sh fichier.json`) ;
`lib/types-coque.ts` en tire les formes de la coque (`Schema<'Moi'>`… avec `role: Role`).
`lib/types-provisoires.ts` ne garde que ce que l'OpenAPI ne publie pas encore (`MatiereResumee`
de la route 70, `SignalementCreation` de la route 222) : à remplacer par `Schema<…>` par D1 / D3.

## À aligner avec les lots serveur
- **D4** (commandes, réceptions) : déclarer `contexte.COMPTEURS["a_approuver"]` (bons à approuver,
  pour la direction) et `contexte.COMPTEURS["receptions_brouillon"]` (D, A) ; les pastilles des
  Commandes et des Réceptions les lisent déjà. **D8** : `alerte_rouge` (C), `anomalies` (D, A).
- **D10** : `contexte.alerte_serveur` est une phrase, affichée telle quelle en rouge (D, T).
- **S2** : désactiver un compte ferme ses sessions, si bien que l'écran ouvert reçoit
  « Connectez-vous pour continuer. » et dit « Votre session a expiré » au lieu de « Ce compte
  n'est plus actif » : garder une trace de la raison de fermeture (ou rendre `compte_inactif`)
  donnerait le bon motif (H-09). `contexte.menu` (domaines de l'API) n'est pas lu : l'écran se
  fie à `routes.ts`, rejoué contre la matrice par les recettes.
- **Recherche** (`recherche.source`) : `lien` doit être une adresse d'écran PRO déclarée
  (`/lots/12`, `/commandes/12`…) ; l'écran retire tout résultat que le rôle ne peut ouvrir.
- **Notifications** : idem pour `lien`.
