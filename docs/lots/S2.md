## Déclarer les droits d'une route

```python
from gestion_mp_pro.securite import C, D, A, L, T, TOUS, QuiDep, droit, exiger

@routeur.get("/lots", response_model=list[LotResume], dependencies=[droit(*C)],
             summary="…", responses=reponses(401, 403))
def lister(qui: QuiDep, s: SessionDep) -> list[LotResume]: ...
```

- `droit(*roles)` rend un `Depends` : **toute** route de l'API le porte, sauf les six publiques
  (`securite.PUBLIQUES` : 1, 2, 8, 9, 10, 22). Aucun passe-droit : nommer `D` partout où la
  direction passe ; `T` (administrateur) seulement sur les routes techniques.
- `QuiDep` = la personne connectée, typée `services.comptes.Acteur` (id, identifiant, nom, role,
  requete, adresse, session, appareil_id, `voit_prix`) ; même dépendance que
  `api.dependances.ActeurDep` (un seul calcul par requête). Les services reçoivent cet `Acteur`.
- 401 « Connectez-vous pour continuer. » sans session ; 401 `compte_inactif` « Ce compte n'est
  plus actif. » ; 403 « Cette action est réservée à : responsable achats. » (KR14 mot pour mot :
  la direction n'est citée que si elle est seule permise, « la direction »).
- Droits fins (un geste dans une route ouverte à plusieurs rôles) : `exiger(qui, "approuver")`,
  `peut(qui, geste)` ; table `securite.GESTES` (voir_prix, liberer_quarantaine,
  mettre_en_quarantaine, approuver, monter, clore_periode, gerer_comptes) ; un domaine ajoute
  les siens par `securite.declarer_geste("nom", D, A)` (à l'import de son `routes.py`).
  `/moi` rend `droits` = les gestes du rôle.
- Matrice : `make matrice` (→ `backend/tests/matrice_droits.csv`, colonnes `methode;chemin;
  anonyme;direction;achats;alimentation;administrateur`, valeurs `ok`/`401`/`403`). Régénérer et
  committer le CSV dans chaque lot D ; l'essai `test_matrice_droits` échoue sinon.

## Se protéger des prix

- Rien à faire pour les réponses JSON : `securite.RouteSansPrix` (posée sur tous les routeurs
  par `communs.nouveau_routeur`) met à `null`, pour tout rôle hors `{direction, achats}`, à
  toute profondeur, les clés de `securite.CLES_MONETAIRES` : `prix*`, `montant*`, `valeur*`,
  `cout*`, `cmup*`, `budget*`, `cours*`, `taux_droits`, `economie*`, `revient*`, `tva*`,
  `droits*`, `frais*`, `devise_prix`, `*_mad`.
- Donc : **nommer** tout champ monétaire selon ces motifs (`valeur_mad`, `prix_kg`,
  `droits_douane`…) ; ne **pas** nommer ainsi un champ qui n'est pas un montant. Si c'est
  inévitable, le schéma de sortie déclare `cles_non_monetaires: ClassVar[frozenset[str]] =
  frozenset({"droits"})` (exemple : `Moi.droits`, la liste des gestes) — l'exemption vaut pour
  toute la réponse de la route.
- Une différence « champ → valeur » s'écrit avec le nom du champ en **clé** (`{"prix": 2.5}`),
  jamais `{"champ": "prix", "valeur": 2.5}` (le filtre ne verrait pas le prix).
- Documents HTML, xlsx, SVG, textes : pas filtrés ; à chaque domaine (barrière 4).
- L'essai `test_prix_masques.py` balaie toutes les routes GET en rôle alimentation sur une base
  qui contient des prix : chaque lot D y ajoute ses données (fabriques) si besoin.

## Journaliser

```python
from gestion_mp_pro.services import audit
with audit.suivre(s, qui, "modification fournisseur", fournisseur, detail=f.nom) as geste:
    fournisseur.nom = …            # seuls les champs changés vont dans avant/après
audit.creation(s, qui, "création fournisseur", f)        # après = la fiche
audit.suppression(s, qui, "suppression opération", op)   # avant = la fiche
audit.journal(s, qui, "validation réception", "reception", r.id, numero=r.numero, detail=…)
audit.verifier_version(s, fiche, version_lue, "Cette commande")  # 409 conflit_version
```

Écrit dans la transaction du geste ; colonnes techniques (`version`, `texte_recherche`,
`modifie_le`…) et secrets exclus. `qui=None` = « système ». L'historique d'une fiche est
`GET /api/historique/{objet}/{id}` (rôles de lecture par objet : `services/audit` côté S2).

## Décisions (documents muets ou contradictoires)

1. **`securite` est un paquet**, pas un module (plafond de 400 lignes) ;
   `python -m gestion_mp_pro.securite matrice` marche ; une ligne du `Makefile` (S0) adaptée
   (`exige … securite` au lieu de `securite.py`), sans quoi `make matrice` refusait de tourner.
2. Services ajoutés hors liste de LOTS : `sessions.py`, `utilisateurs.py`, `journal.py`,
   `contexte.py` (plafond de 400 lignes, aucun cycle d'import).
3. **Connexion par visage** : `/visages` ne donne plus l'identifiant (F-02) mais l'`id` ;
   `Connexion` accepte donc `compte` (id) **ou** `identifiant`. `compte` n'est accepté que du
   poste local (`127.0.0.1`, `::1`) ou d'un appareil enrôlé (sinon 403 `poste_non_autorise`) :
   l'id n'est pas un identifiant à deviner depuis le réseau.
4. `UtilisateurModification` accepte un **`code` facultatif** : un changement de rôle qui exige
   un nouveau code (vers ou depuis l'alimentation, ou plus long) se fait en une requête (sans
   lui, le `PUT` refusait et `POST …/code` refusait aussi : impasse). Message F-01 mot pour mot.
5. Règles de code : alimentation exactement 4 chiffres ; achats, direction 8 ; **administrateur
   12** (MODELE-DONNEES § 3.1.1). Message « Le code doit faire au moins 12 caractères. ».
6. **Désactiver ferme les sessions** (ARCHITECTURE § 5.1 ; Gestion MP corrigé les gardait
   jusqu'à la réactivation) ; une session d'un compte inactif (écriture directe) reçoit 401
   `compte_inactif` « Ce compte n'est plus actif. ». Changer de rôle ou de code ferme aussi les
   sessions (sauf celle d'où l'on agit sur soi) et lève le blocage du compte.
7. **Toujours une direction active** : 409 `derniere_direction` « Il doit toujours rester un
   compte de direction actif : en créer ou en réactiver un autre d'abord. » (directions
   verrouillées `FOR UPDATE`). Soi-même : rôle et état figés pour tous (message de Gestion MP
   pour la direction ; « Vous ne pouvez ni changer votre propre rôle ni vous désactiver. »
   pour les autres). Un compte `historique` (reprise) ne se modifie pas (409).
8. Message 403 (KR14) : la direction n'est citée que si elle est seule ; `droit(D, T)` →
   « Cette action est réservée à : la direction, l'administrateur technique. ».
9. Le filtre des prix vaut pour **tout rôle hors D et A** (alimentation, administrateur,
   anonyme) : l'administrateur ne lit pas les prix des `avant`/`apres` du journal (C8) ; les
   **phrases** (`detail`) ne sont pas filtrées (limite déclarée). `devise` n'est pas une clé
   monétaire (absente de la liste d'API-PRO, alors que Gestion MP la vidait) : un lot qui veut la
   cacher le fait par un schéma réduit.
10. `droits*` (droits de douane) attrape aussi `Moi.droits` (gestes permis) : mécanisme
    d'exemption `cles_non_monetaires: ClassVar` sur le schéma de sortie.
11. Historique (route 51) : garde `droit(*TOUS)` (« droit de lecture de la fiche »), puis table
    `journal.LECTURE_HISTORIQUE` par objet (403 au message KR14) ; l'administrateur ne lit que
    les fiches techniques (comptes, appareils, sauvegardes, reprise, système).
12. Purge : sessions expirées depuis 7 jours et tentatives de plus de 30 jours non bloquées
    (MODELE-DONNEES), à chaque connexion et par la tâche ; notifications lues depuis 90 jours.
13. « Dernière activité » (`vu_le` du compte et de la session) notée au plus une fois par
    minute, par une connexion à part, en SQL direct : la `version` du compte ne bouge pas.
14. Installation : « Gestion MP PRO est déjà installé : connectez-vous. » (nom du produit) ;
    sous `LOCK TABLE utilisateur` (deux installations simultanées : une seule passe).
    `GET /etat` rend aussi `version`.
15. Exemple de KR35 : `http://mac-usine:8050` (port de PRO).
16. Période close : `clore()` est dans `services/periode.py` (ARCHITECTURE § 3) ; motif ≥ 3
    (« Le motif est obligatoire : 3 caractères au moins. »), « On ne clôt qu'une période
    passée. », brouillons et inventaires ouverts datés de la période refusés (E-14, message de
    Gestion MP), historique avec motif, journal `paramètre` objet `periode` avec avant/après.
17. Journal : filtre `utilisateur` par **id** (le nom est une copie) ; recherche de 6 mots au
    plus, sans accents des deux côtés (`translate` des lettres accentuées), dans le nom,
    l'action, l'objet, le numéro et la phrase ; curseur = id ; `du > au` → 422.
18. Numérotation : 4 chiffres (`LOT-2026-0001`, cahier I75 non suivi : le code de Gestion MP
    fait foi) ; `DOS` `NN/AA` ; `deja_pris` et `rattraper` pour la reprise et les lots repris.
19. `/contexte` : `menu` = domaines de l'API où le rôle lit/écrit (dérivé de la matrice),
    plus `compteurs`, `base_essai`, `roles_au_metre`, `alerte_serveur` (D, T seulement ; par
    défaut : écoute réseau sans HTTPS).
20. Une connexion réussie efface les essais du compte **et** de l'adresse ; un essai fait sur
    une adresse bloquée compte quand même pour le compte (comme Gestion MP corrigé).
