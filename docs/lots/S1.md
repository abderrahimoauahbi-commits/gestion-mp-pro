## Décisions (MODELE-DONNEES muet, contradictoire, ou en retard sur Gestion MP corrigé)

1. **Étape 15 de Gestion MP** : `reclamation.reception_ligne_id` (facultatif), FK composite
   `(reception_ligne_id, reception_id)` → `reception_ligne(id, reception_id)` et CK
   `ck_reclamation_ligne_de_reception` (une ligne nommée ⇒ sa réception nommée).
2. **Étape 16** (`dossier_ligne.cours_fige_cloture`) : **pas de colonne** ; c'est
   `cours_origine = 'clos_au_jour'`. CK `ck_dossier_ligne_cours_origine` :
   `(cours IS NULL) = (cours_origine IS NULL)` — tout cours dit d'où il vient (la reprise met
   `reprise` à défaut). La réouverture d'un dossier remet `cours` **et** `cours_origine` à NULL
   pour les lignes `clos_au_jour`.
3. **Étape 17** : `StatutInventaire` gagne `annule` (inventaire validé puis défait par
   contre-passation) avec `annule_le`, `annule_par_id`, `annulation_motif` ; `valide_le` reste
   posé sur un inventaire annulé (CK `(statut IN ('valide','annule')) = (valide_le IS NOT NULL)`).
   `inventaire_ligne` : `matiere_id` **obligatoire** (FK composite avec `lot_id`), `lot_id`
   facultatif (lot trouvé, créé à la validation), `lot_numero`, `lot_interne` (case « LOT
   INTERNE ») ; CK : un lot se désigne (`lot_id`, `lot_interne` ou `lot_numero`), une ligne sans
   lot est un lot trouvé, un lot trouvé a un théorique nul ; index unique partiel
   `uq_inventaire_ligne_lot_a_creer` (même matière, même numéro, même magasin, une fois).
4. **Étape 18** généralisée : **chaque** colonne `NUMERIC` refuse `NaN` (`ck_<table>_<col>_nombre`,
   74 CHECK) — en PostgreSQL `'NaN' >= 0` est vrai. L'infini est refusé par PostgreSQL lui-même.
   UQ `(ordre_id, qualite_id)` était déjà au document.
5. **Réglages : 57 clés** : les 56 de Gestion MP corrigé (dont `delai_frais_import_jours`,
   défaut 30, bornes 1–365, ajouté par l'équipe E pour C28, et `toler_tva_import`, défaut 0,05,
   bornes 0–1, en %, lu par C29 et la fiche du dossier, Gestion MP 26459d4, semé par la révision
   0003) **et** `seuil_bc_urgent` (300 000), sans effet mais gardé pour mémoire (ECRANS-PRO E6).
   Liste fermée : `modeles.CLES_REGLAGES`, CK `ck_parametre_cle_connue`. Valeurs semées normalisées (entier sans « .0 » : `croissance_annuelle`
   = `0`, `seuil_surcout_import` = `1`), `modifie_par_id` NULL (= installation).
6. Les CHECK suivent la convention `ck_<table>_<nom>` : `ck_role_nomenclature_lineaire_de_base`
   (doc : `ck_role_lineaire_de_base`), `ck_poste_frais_tva_recuperable` (doc :
   `ck_poste_tva_recuperable`), `ck_piece_jointe_un_objet` (doc : `ck_piece_un_objet`). Le CHECK
   d'une énumération est posé par `completer_le_schema` (pas par le type `Enum`) : la révision le
   porte en clair, indépendante de la convention du moment.
7. `journal.objet` : défaut **`systeme`** (le `''` du document est hors énumération) ;
   `ObjetJournal` gagne **`lot`** (le commentaire de la fiche de lot s'édite et a un historique).
8. `journal.requete` en `VARCHAR(16)` (un `CHAR(16)` vide se remplit d'espaces).
9. `commande` : CK `ck_commande_cours_mad` (MAD ⇒ cours NULL, incohérence 8 « partout »).
10. CHECK ajoutés pour la cohérence statut ↔ date : `ordre` et `operation` (annulation),
    `operation` (validation), `dossier` (clôture, annulation, `annee`/`rang` ensemble et bornés,
    `saisi_a_la_main OR rang IS NOT NULL`, format `^[0-9]{1,3}/[0-9]{2}$` ou `^ANC-`) ;
    `facture` et `dossier_frais` (`payee_par_id` ⇒ `payee_le`) ; `piece_jointe` (objet cohérent
    avec sa clé, retrait daté et signé ensemble) ; `inventaire_critere` (genre cohérent avec sa
    colonne) ; `reprise_execution` (fin ⇔ statut terminé) ; `plan_version` (motif de restauration,
    comme `recette_version`) ; `recette_version.numero >= 1` ; bornes d'étage (1–40).
11. FK composites ajoutées : `dossier_frais (ligne_id, dossier_id)` → `dossier_ligne(id, dossier_id)`
    (un frais rattaché l'est à une marchandise de **son** dossier) et celle de la réclamation (1).
    `matiere (id, role_id)` unique comme demandé, mais aucune FK ne s'en sert (une version de
    recette fige le rôle de son époque).
12. `ON DELETE` : `commande_decision` **CASCADE** (un brouillon renvoyé reste supprimable ; le
    journal garde la trace) ; `montage → metier_etage` CASCADE ; `dossier_frais_part.ligne_id`
    RESTRICT (comme `dossier_frais.ligne_id`).
13. `ordre.texte_recherche` a aussi son index GIN (§ 8 l'omettait). `ix_signalement_a_traiter`
    indexe `quand` des signalements non traités (le document indexait `traite_le`, toujours NULL).
14. `motif.impose_role` : seulement « Libération de quarantaine » → `achats` (la direction passe
    toujours) ; « Mise en quarantaine » : NULL (le transfert est déjà permis à l'alimentation).
15. Le modèle de la table `session` s'appelle **`SessionOuverte`** (pas de confusion avec la
    `Session` de SQLAlchemy).
16. `reprise_correspondance.id_source/id_cible` en `BIGINT` (journal, mouvements) ;
    `reprise_execution.empreinte_source` et `comptes` facultatifs.
17. Les libellés d'écran des énumérations restent dans `frontend/src/lib/statuts.ts` (E0), pas
    dans `enums.py`.

## Pour S2 (sécurité, audit, socle métier)

- `services/recherche.normaliser()` : réutiliser `modeles.recherche.normaliser` (même règle que
  l'écran). La recherche « tous les mots » : `texte_recherche LIKE '%mot%'` par mot, échappé.
- `version_id_col` est posé sur : utilisateur, parametre, devise, composition, type_fil, titrage,
  couleur, code_douanier, fournisseur, matiere, qualite, magasin, metier, metier_etage,
  poste_frais, commande, facture, reception, ordre, operation, inventaire, dossier,
  dossier_frais, reclamation. Une mise à jour périmée lève `sqlalchemy.orm.exc.StaleDataError`
  (à traduire en 409). Pour exiger la `version` reçue de l'écran, comparer avant d'écrire.
- Erreurs de base : chaque contrainte a un **nom stable** (`diag.constraint_name`) ; les
  déclencheurs lèvent `restrict_violation` (`tr_mouvement_immuable`, `tr_operation_type_fige`)
  ou `check_violation` (`tr_matiere_lineaire_densite`, à la validation de la transaction ou à
  `SET CONSTRAINTS … IMMEDIATE`) avec leur nom en `CONSTRAINT`.
- `utilisateur.historique` : compte de la reprise, jamais connecté (CK : historique ⇒ inactif,
  et seul un historique peut être sans rôle).
- `parametre_historique.cle` est une FK vers `parametre.cle` ; `devise_cours` reçoit les cours.
- Défauts « instant » : l'ORM prend `horloge.maintenant()` (figée dans les essais), le serveur
  `now()`. `modifie_le` est posé par l'ORM à chaque `UPDATE` (`onupdate`), `modifie_par_id` par
  le service.

## Pour S4 (stock) et les lots D

- Toutes les relations sont `lazy="raise"` : `selectinload`/`joinedload` explicites.
  Collections (cascade, `passive_deletes`) : `Commande.lignes/versions/decisions`,
  `CommandeVersion.lignes`, `Reception.lignes`, `Ordre.qualites/lignes/prevus`,
  `Operation.lignes`, `Inventaire.criteres/matieres/lignes`, `Dossier.lignes/frais`,
  `DossierFrais.parts`, `Qualite.poids/saisons/recettes`, `RecetteVersion.lignes/poids`,
  `PlanVersion.saisons`, `Metier.etages_montes/montages`. Lecture seule : `Lot.matiere`,
  `Solde.lot`, `Mouvement.lot`, `Matiere.role`, `Matiere.fournisseur`.
- Écrire en `Decimal` arrondi par `types.arrondir(valeur, QUANTITE)` (refuse NaN, infini, hors
  colonne). `solde.quantite >= 0` est **exact**.
- `mouvement` : CK `ck_mouvement_document` (une seule clé de document, cohérente avec `document`),
  `ck_mouvement_ordre`, `ck_mouvement_prix_entree`, `ck_mouvement_cours_mad` ; contre-passation
  unique (`uq_mouvement_contrepasse_id`).
- `texte_recherche` est tenu par l'écouteur `before_flush` (fiches nouvelles ou modifiées ; un
  renommage de fournisseur, de matière, de classification ou de métier met à jour les fiches qui
  le citent). Champs : fournisseur (nom, code, pays, contact) ; matière (référence, désignation,
  codes de classification, fournisseur, code couleur, groupe) ; lot (numéro, référence et
  désignation de la matière) ; qualité (code, nom) ; commande (numéro, fournisseur, conteneur,
  navire) ; réception (numéro, fournisseur, BL, contrôlé par) ; dossier (numéro, libellé, banque) ;
  ordre (numéro, métier, commentaire).
- **D5** : un inventaire ouvert par magasin (`uq_inventaire_ouvert_magasin` sur
  `coalesce(magasin_id, 0)`) ; le global contre les autres reste au service (verrou
  `INVENTAIRE_GLOBAL`).
- **D7** : un dossier annulé libère sa facture (`uq_dossier_facture` partiel) mais
  `dossier_ligne.reception_ligne_id` est unique **pour tous les dossiers** : à l'annulation, le
  service détache ses marchandises (`reception_ligne_id = NULL`) pour qu'un nouveau dossier les
  reprenne. Numéro automatique : `annee` + `rang` (UQ) ; `numero` libre seulement si
  `saisi_a_la_main`.
- **D2** : `recette_version.numero` est unique par qualité (`uq_recette_version_qualite_id_numero`) ;
  une restauration exige un motif (CHECK), pour les recettes comme pour le plan.
- **D3** : `commande.parti` est une colonne générée (lecture seule) ; `solde_origine` est posé
  si et seulement si le bon est soldé ou annulé ; un cours figé a sa date (`cours_fige_le`).

## Migrations : règles pour la suite

- Nouvelle révision : `cd backend && .venv/bin/alembic -x base=postgresql+psycopg:///<base>_essai
  revision --autogenerate -m "…"` : numérotée à la suite (`0003`), formatée par ruff, puis relue :
  **aucun import du paquet**, DDL en clair (essai `test_aucune_revision_n_importe_le_paquet`).
  Autogenerate ne voit ni les CHECK modifiés, ni les déclencheurs : les écrire à la main ;
  `test_schema_migre_identique_au_schema_des_modeles` compare colonnes, contraintes et index de
  la base migrée à ceux des modèles.
- Pas de `%` dans le texte d'un CHECK (il serait doublé par le rendu) : utiliser `~`.
- `alembic check` sans argument (cible de `make verifier`) vise `gestion_mp_pro_essai`
  (`[gestion_mp_pro] base_de_controle` d'`alembic.ini`) si `GESTIONMPPRO_BASE` n'est pas posée ;
  `-x base=…` l'emporte toujours.
- Les essais de `test_migrations.py` vident la base d'essai puis la remigrent : ne pas compter
  sur des données laissées par un autre essai.
