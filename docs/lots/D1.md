# Lot D1 — référentiels et réglages : ce que les lots suivants doivent savoir

Branche `lot-D1`. `make verifier` vert (ruff, format, mypy strict, pytest : 1 436 essais dont
98 de D1, `alembic check`, écran). Routes faites : **23–42** (réglages, période close, devises,
magasins, postes de frais, codes douaniers, motifs) et **57–81** (classification, fournisseurs,
matières, référence composée, classement, tableur, exports). Aucune révision Alembic, aucun
fichier d'un autre lot modifié.

## 1. Fabriques des référentiels (`tests/fabriques/referentiels.py`) — pour tous les lots D

```python
from fabriques.referentiels import (fournisseur, matiere, devise, magasin, magasin_seme,
    poste_frais, poste_seme, code_douanier, qualite, role_id, valeur_classification,
    stock_initial, unique)

usd = devise(cours="10.5")                       # code tiré au hasard, cours historisé
f = fournisseur(devise=usd, pays="turkey")       # rend l'id ; nom unique
m = matiere(fournisseur_id=f, prix="2.5", devise=usd)   # Poil, en service ; fournisseur créé s'il manque
cuir = matiere(role="Cuir", unite_prix="ml", prix="0.5")  # densité 0,014 posée d'office
q = qualite(recette={m: 100}, poids={"Poil": "1.2"})     # qualité minimale (sans contrôle des 100 %)
lot = stock_initial(m, "42.5", magasin_id=magasin_seme("quarantaine"))  # par services/stock (S4)
```

- Sans `s=` : une session à soi, **validée** (l'API voit la donnée). Avec `s=` : dans la
  transaction de l'essai (annulée à la fin). Écriture directe, sans journal ni contrôle.
- Noms, codes et références uniques par défaut (`unique("REF")`) : la base est partagée par la
  séance, et `test_migrations` peut la remigrer.

## 2. Services utiles aux autres lots

| Service | Pour qui | Ce qu'il donne |
|---|---|---|
| `reglages.nombre(s, cle)`, `reglages.texte(s, cle)` | tous | la valeur d'un réglage (défaut si vide ou illisible) |
| `registre_reglages.PAR_CLE`, `REGLAGES` | F8, D8, D10 | les 57 déclarations (libellé, famille, bornes, unité, échelle, aide, `technique`, `modifiable`) |
| `fournisseurs.est_local(pays, devise)` | **D7** (A-23) | la **seule** définition du fournisseur local : pays MAROC, MOROCCO ou MA ; sans pays, en MAD |
| `matieres.commandable(s, matiere_id)` | **D3, D4** (A-11) | 409 `fiche_inactive` « « X » est désactivée : la réactiver avant de la commander. » ou « « F » est désactivé : le réactiver avant de lui commander. » ; à la réception sur un bon : avertir seulement |
| `matieres.verifier(s, champs, actuel)`, `BORNES` | D2, tableur | les règles d'une fiche (ordre de Gestion MP corrigé) |
| `matieres_lecture.conditionnement(m)`, `prix_kg(...)` | D3, D6, D8 | conditionnement déclaré ou déduit (palette, bobine, kg) ; prix ramené au kilo |
| `referentiels.TYPES_MOTIF` | **D5** | type d'opération → (libellé, rôles qui le font) ; le motif « Libération de quarantaine » exige en plus `achats` (`motif.impose_role`) |
| `referentiels.MOTIFS_RECLAMATION`, `ISSUES_RECLAMATION` | D4, F4 | libellés des motifs et issues de réclamation (servis par `GET /motifs`) |
| `devises.figer_cours_periode_close(...)` | D7 | E-02 : fige le cours des marchandises de dossiers ouverts entrées en période close |
| `postes_frais.repartir(montant, poids)` | D7 | parts au centime, Σ = montant, plus forts restes, signe gardé |

**Période close** : `devises.figer_a_la_cloture` est inscrit dans `periode.APRES_CLOTURE` (à
l'import de `services/devises`) : à la clôture, les marchandises sans cours des dossiers
ouverts entrées dans la période prennent le cours du jour (`cours_origine = 'periode_close'`
depuis la révision 0004, lot RESTES1 ; le commentaire n'est plus touché). **D7** n'a pas à le réinscrire (il est idempotent : une ligne qui a un cours
n'est pas retouchée) ; D7 garde `clos_au_jour` pour la clôture d'un **dossier**.

## 3. Décisions (documents muets ou contradictoires)

1. **Route 24** : corps `{valeurs: {clé: valeur}, version_globale}` ; `version_globale` = Σ des
   `version` des 57 lignes de `parametre` (rendue dans chaque `Reglage`, avec la `version` de la
   ligne) ; périmée → 409 « Les réglages ont été modifiés entre-temps par {nom} ({heure}) :
   rouvrez-les pour repartir de leur dernière version. ». Tout ou rien : les ordres sont
   vérifiés sur l'état final **avant** d'écrire (pas de rollback après coup).
2. Ordres : ceux de Gestion MP corrigé (critique < attention, A < B, Tier 3 < Tier 2, X < Y,
   ATTENTION < standard < stratégique, **Tier 2 ≤ Tier 1**), messages mot pour mot.
3. Familles : les 9 de Gestion MP + **« Période close »** (`date_cloture`, `modifiable=false`,
   écrite par la route 26 seulement : 422 sinon) + **« Technique »** (`courriel_destinataires`,
   `adresse_publique`, `technique=true`) ; l'administrateur lit et écrit cette famille seule
   (403 « Cette action est réservée à : la direction. » pour le reste). `seuil_bc_urgent` :
   lisible, `modifiable=false`, 422 à l'écriture (E-16). Aides d'écran de Gestion MP versées dans
   le registre ; aides écrites pour `score_*`, `seuil_hausse_forte`, `dso` ; exemple de
   l'adresse publique en `:8050`.
4. **Route 26** : `ClotureEntree` reçoit aussi `version` (celle de la ligne `date_cloture`, rendue
   par `Periode.version`) : une clôture est une écriture (409 si périmée).
5. Devises : le code se valide en service (« Le code d'une devise s'écrit en trois lettres (EUR,
   USD, CNY…). ») ; une devise hors service ne se pose pas sur une fiche si elle change ;
   `DeviseFiche.cours_repris` = aucun cours saisi depuis la mise en service.
6. Magasins : code unique sans tenir compte de la casse ; **il reste toujours un magasin en
   service de chaque type** (R-REF-04) ; type accepté en `stock_courant`/`quarantaine` (ou le
   libellé), refus mot pour mot ; milliers « 1 234 » dans les messages (I-15).
7. Rôles de nomenclature : l'entrée n'a pas de `lineaire` (API-PRO : `{code, ordre}`) : un rôle
   ajouté se compte **au poids** (seuls Cuir, Franges, Ruban, de base, vont au mètre). Un rôle
   ajouté se renomme même s'il est porté (clé technique `id`, A-13 au-delà du minimum) ; il ne
   se supprime pas s'il est porté (matières, poids > 0) ni s'il figure dans l'historique (versions
   de recette, critères d'inventaire).
8. Classification : codes uniques sans tenir compte de la casse (« « PP » existe déjà (« pp »). »),
   longueur de la colonne (A-06) ; désactiver une valeur portée rend `avertissement`.
9. Matières : par **ids** (rôle, classification, fournisseur, code douanier) ; référence unique
   sans casse ; désactiver ne revalide que ce qui change (H-28 : une fiche sans fournisseur se
   désactive) ; une valeur de classification, un fournisseur ou un code douanier **désactivés** ne
   se posent pas s'ils changent (A-11). L'alimentation ne lit ni prix, ni `devise`, ni
   `unite_prix`, ni `minimum_commande` (`null`). Traces qui empêchent la suppression : celles de
   Gestion MP + versions de bon, prévus d'ordre, inventaires, signalements, versions de recette.
10. Classement (77) : corps `{ids, versions}` ; seules les matières choisies, à leur version.
11. Tableur : colonnes du modèle + « Priorité dans le groupe », « Vider » (colonnes à vider
    séparées par « ; » ; Référence, Rôle, Unité du prix, Devise, En service ne se vident pas),
    « Version » (ligne refusée si la fiche a changé depuis le modèle). `empreinte_apercu` =
    empreinte du **plan d'écriture** : l'application refait le plan et refuse (409) s'il
    diffère. Une matière nouvelle n'exige un fournisseur que si elle est en service. 10 Mo et
    10 000 lignes au plus.
12. `GET /motifs` rend aussi les motifs et issues des réclamations (ECRANS-PRO « une source »).
13. DELETE 41, 63, 68, 74 : `?version=` **facultatif** (contrôlé s'il est donné ; API-PRO ne le
    prévoit pas) ; 37 : obligatoire (API-PRO).
14. Classeurs (69, 78, 81) : `exports/referentiels.classeur` applique les conventions de Gestion MP
    (titre daté, intitulés gras, volet, filtre, formats) en attendant `exports/classeur.py` (D9).

## 4. Écarts aux documents (à reporter par le coordinateur)

- **MODELE-DONNEES** : `role_nomenclature` n'a pas de colonne `version` ; API-PRO 59 la demande
  (`RoleModification.version`) : acceptée mais **non contrôlée**. Demande à S1 : ajouter
  `version` (révision à réserver), puis brancher `audit.verifier_version` dans
  `classification.modifier_role`.
- **MODELE-DONNEES** : `OrigineCours` n'a pas de valeur pour un cours figé par la période close
  (E-02) : `saisi` est employé, avec la note dans le commentaire. Proposé : `periode_close`.
- **API-PRO § 1.3** : 24 (corps), 26 (+ `version`, `Periode.version`), 27 (+ `cours_repris`),
  28 (`CoursHistorique` {id, cours, saisi_le, par, variation}), 31 (+ `version`), 34 (`PosteFiche`
  + `entre_valeur_douane`, `dossiers_ouverts`, `dossiers_clos`, `utilise`, `version`), 38
  (`CodeDouanierFiche` {…, nb_matieres, version}), 42 (+ `reclamation_motifs`,
  `reclamation_issues`).
- **API-PRO § 1.7–1.9** : 57 (`RoleFiche` sans `version`), 62 (+ `avertissement`), 64 (sortie
  `FournisseurFiche | FournisseurResume`, + `empechements`, `nb_*`, `local`, `devises`), 70–71
  (champs de `MatiereResume`/`MatiereFiche` : codes **et** ids de classification, `usages`),
  77 (`{ids, versions}`), 79–80 (`empreinte_apercu` en champ de formulaire, compteurs).
- **ECRANS-PRO P7 « Désactiver »** dit « corps partiel » alors qu'API-PRO § 1.24 dit « fiche
  entière » : la fiche entière est exigée (API-PRO), désactiver ne revalide que ce qui change.
