# Lot S0 — socle du dépôt et du serveur : ce que les lots suivants doivent savoir

Branche `lot-S0`. `make verifier` vert : ruff, ruff format, mypy strict (`services/`, `calcul/`),
pytest (266 essais), écran (`npm run verifier`). Python 3.12, FastAPI 0.143, Starlette 1.7,
SQLAlchemy 2.1, Pydantic 2.14 (versions figées dans `backend/requirements.lock` et
`requirements-dev.lock` ; `make verrouiller` les refige).

## Décisions
1. `X-Heure-Serveur` = instant de l'usine **avec décalage** (`2026-10-08T10:00:00+00:00`,
   `isoformat(timespec="seconds")`), demandé par E0.
2. Un 500 imprévu dit « Erreur du serveur (réf. a1b2c3d4). » : la référence est le **début (8
   caractères)** de `X-Requete` (16 hex) ; le journal porte `requete=<16> ref=<8>` et la pile.
3. `période close` → **409** `periode_close` (API-PRO § 0.3), alors que Gestion MP disait 422 ;
   `date_future`, `date_trop_ancienne` restent 422. Le message reste mot pour mot.
4. Statut HTTP **tiré du code** : `CODES` (`api/erreurs.py`, 63 codes) dit le statut de chaque
   code ; `Refus("code_inconnu", …)` ou `Refus.saisie(…, code="bon_clos")` lèvent `ValueError`
   (faute de programmation, attrapée par les essais). Ajout de code : demande à S0/coordinateur.
5. Traduction des 422 : remplacements de Gestion MP **dans le même ordre** (« Texte trop court :
   au moins 3 caractères », « La valeur doit être au plus 10 », « à renseigner ») ; en plus, les
   types qui sortaient en anglais ont leur phrase (« nombre entier attendu », « champ inconnu »,
   « date attendue (AAAA-MM-JJ) »…), le préfixe « Value error, » est retiré, et `champs` donne
   le message par chemin (`lignes.0.quantite`). Corps illisible / non UTF-8 → 422, jamais 400.
6. 405 a son code (`methode_non_permise`) ; une `HTTPException` de bibliothèque est remise à la
   convention `{detail, code}`.
7. Disponibilité (`db.Disponibilite`) : 503 `schema_en_retard` (posé au
   démarrage), `restauration_en_cours` (verrou consultatif RESTAURATION tenu par une session de
   **cette** base, lu dans `pg_locks` au plus toutes les 2 s), `base_indisponible`. Toujours
   servis : `/api/sante`, `/api/etat`, `/api/docs`, `/api/openapi.json`.
8. CSP posée par l'application aussi (pas seulement Caddy), sauf sur `/api/docs` (Swagger).
9. `GET /api/sante` : première forme posée par S0 (`etat`, `version`, `base_ms`, autres champs
   d'API-PRO à `null`/vides) pour l'écran d'attente d'E0. `version` = fichier `VERSION` à la
   racine (copie figée) sinon « 0.1.0 (projet) ». E0 lit aussi `heure`, absent d'API-PRO :
   non ajouté (l'heure vient de `X-Heure-Serveur`).
10. Sauvegardes et pièces : `GESTIONMPPRO_SAUVEGARDES` / `_PIECES` sont des **racines** ; le
    dossier réel est `<racine>/<nom de la base>` (`Reglages.dossier_sauvegardes`, `.dossier_pieces`).
11. Pas de fichier `.env` lu par l'application : environnement seulement (systemd
    `EnvironmentFile`, Compose `env_file`).
12. `httpx2` (et non `httpx`) pour le client d'essai : Starlette 1.7 l'exige.

## Crochets laissés (aucun fichier de S0 à modifier)
- **S1** : `services/installation.py` avec `migrer()` (Alembic sous `db.Verrou.MIGRATION`) —
  appelé par `tests/conftest.py` après `DROP SCHEMA public CASCADE` et par le démarrage de
  l'application (`main._mettre_le_schema_a_jour`) ; facultatif `schema_en_retard() -> bool`
  (révision ≠ head) lu après la migration. Un échec de `migrer()` au démarrage → API en 503.
  Les modèles et `Base` sont à S1 (`modeles/base.py`) : `db.py` n'en déclare pas.
  `make verifier` lance `alembic check` dès que `backend/alembic.ini` existe.
  `pyproject.toml` embarque déjà `migrations/*.mako` et `documents/gabarits/*`.
- **S2** : `securite.py` fournit `acteur_de_la_requete(requete, session) -> Acteur` (attributs
  `id, identifiant, nom, role`) ; `api/dependances.acteur` / `ActeurDep` y délèguent (401 tant
  que `securite` n'existe pas). Poser `requete.state.acteur` pour que la ligne du journal dise
  `utilisateur=… role=…`. Pour le filtre des prix : définir `securite.RouteSansPrix`
  (sous-classe d'`APIRoute`) ; `api/communs.nouveau_routeur()` la prend automatiquement pour
  **tous** les routeurs (les routeurs sont créés à l'import des `routes.py`, après `securite`).
  `droit(...)` devrait dépendre de `dependances.acteur` (même fonction = un seul calcul par
  requête). Cookies et en-tête : `config.COOKIE_SESSION`, `COOKIE_APPAREIL`,
  `ENTETE_ANTI_FALSIFICATION`. Les tentatives de connexion refusées doivent s'écrire dans une
  session à part : la session de la requête est annulée par tout `Refus`.
  `make matrice` attend `python -m gestion_mp_pro.securite matrice` (CSV sur la sortie).
- **S3** : `calcul/` existe (vide) et est sous mypy strict ; aucune base, aucune horloge.
- **S4 et D** : `SessionDep` (jamais `Depends(db.session)` : `scope="function"`, commit avant la
  réponse, rollback sur toute exception) ; `DateReferenceDep` (`?date=`, 2000-01-01 … aujourd'hui),
  `PaginationDep` (`?apres=&limite=`, curseur `communs.encoder_curseur/decoder_curseur`),
  `VersionDep` (`?version=` des suppressions), `communs.Entree` (extra interdits),
  `communs.Sortie`, `Page[T]`, `ValidationVersion`, `Message`, `Ok`, `Personne`,
  `MatiereCourte`, `LotCourt` ; `erreurs.reponses(404, 409)` pour les `responses` OpenAPI.
  Verrous : `db.verrouiller(s, Verrou.ORDRES)` (transaction), `essayer_verrou`/`liberer`
  (session). Horloge : `services.horloge.aujourd_hui()/maintenant()` uniquement.
- **D10** : `taches/planificateur.py` avec `demarrer()` et `arreter()` (appelés si
  `GESTIONMPPRO_TACHES=1`) ; compléter `GET /api/sante` (`api/systeme/`, avec S2) ; la
  restauration tient `Verrou.RESTAURATION` pendant tout son travail et remet
  `db.DISPONIBILITE.schema_en_retard` après sa migration.
- **X1/X2** : lancer uvicorn avec `--no-access-log` (le journal par requête est celui de
  `trace`) ; `GESTIONMPPRO_JOURNAL_FICHIER` pour le fichier tournant (10 Mo × 10) du Mac.

## Règles vérifiées par les essais du socle
`test_structure.py` (tout fichier ≤ 400 lignes, fonction ≤ 60 lignes, docstrings, aucun
`print`, 25 domaines déclarés, `services/` et `calcul/` sans FastAPI) ; `test_config.py` (aucune
lecture de `os.environ` hors `config.py`, défauts, coexistence) — ces essais s'appliquent aussi
au code des lots suivants.
